## A. 識別戦略（Phase 2 の核）— 最重要

推定式: `ΔCPI_{c,t} = β·(IC_c × P_import_t) + γ_t + δ_c + ε`、CPI中分類41×2021-24、two-way FE、entity-cluster SE。

### A-1. 因果主張が過大 [CRITICAL / reframe で対応可]

- **doc の主張**: INDEX.md「因果推論で実証」、research-design.md「コストプッシュ効果を識別」。
- **実体**: `P_import_t` は**集計**輸入物価（`cost_push_panel.py:73` `group=="total"`）。識別変動は「高IC財が高P_import年に多くインフレしたか」のみ。
- **致命的交絡（goods-vs-services）**: IC は財/サービス区分と機械的に相関（輸入の大半は財、サービスは低IC）。コロナ後の**財需要急増・サービス抑制→反発**は category-level の差別的トレンドであり、time FE でも entity FE でも吸収されない。→「高IC財が2021-24に多くインフレ」は cost-push と**整合的だが分離不可能**。
- **競争的輸入財除外は交絡を悪化させうる**: 上昇しなかった高IC財（衣料）を落とし、上昇した高IC財（エネ・食料）を残す。だがエネ・食料は需要非弾力な**必需品**で固有の供給ショックも持つ → 観測的に絡む。
- **5グループの価格差が識別に未使用**: エネ+203% vs 食料+50% という Phase 1 のリッチな変動を、回帰は単一集計 P_import に潰している。
- **推奨**: 「因果的に証明」→「コストプッシュと**整合的な**横断的関連」。識別仮定（デマンドプルのカテゴリ一律性）を明示し、goods-services 交絡を限界として記述。

### A-2. プラセボ検証は無情報かつ ill-conceived [MAJOR]

- **doc の主張**: research-design.md「2015-19 で β≈0 → ショック特有を支持」、contribution.md「プラセボ非有意（β=0.231, p=0.417）→ 識別仮定 supported」。
- **実証検証（本レビューで再推定）**:

  | 仕様 | β | SE | p | 95%CI |
  |---|---|---|---|---|
  | (iii) メイン: 競争的輸入財除外・ショック期 | 0.431 | 0.135 | 0.002 | [0.17, 0.70] |
  | (v) プラセボ: 全41・2015-19（設計表） | 0.231 | 0.284 | 0.417 | [−0.33, 0.79] |
  | **(v') プラセボ: 競争的輸入財除外・2015-19** | **0.540** | **0.387** | **0.165** | **[−0.22, 1.30]** |

- **pooled プラセボ β=0.540 は妥当な falsification ではない**:
  - (ill-conceived) 2015-19 は無ショック期では**ない**。P_import は 98.7→118.1 と **~20pp 変動**（2014-16 原油暴落・回復）。cost-push 転嫁があれば任意の価格変動期で β>0 が出るのが当然 → 非ゼロは想定内で disqualifying でない。しかも `shift_share` は符号反転する `P_import−100` を通すため pooled β の解釈が不安定。
  - (無情報) CI[−0.22, 1.30] は **0 も 0.431 も含む** → 支持も否定もしない。「非有意→ゼロ→supported」は absence of evidence の誤読。⚠ 逆に「プラセボの方が大きい→spurious」と読むのも**同じ誤り**。
- **年次相関は別の estimand であり、こちらが well-posed なテスト**（pooled β とは矛盾しない: 年次相関は**年内の生の横断面＝demean なし**、pooled β は **entity＋year FE 除去後** → 測っている量が違う）。競争的輸入財除外後:
  - ショック期 r: 2021 +0.42 / 2022 +0.59 / 2023 +0.60 / 2024 +0.42（n≈39、相関として有意水準）
  - プラセボ期 r: 2015 −0.08 / 2016 −0.35 / 2017 −0.13 / 2018 +0.09 / 2019 +0.20（多くは非有意）
  - このコントラストは shock-specificity を**方向的に支持**する。
- **推奨**: **年次相関コントラストを主たる falsification 証拠に据える**（pooled プラセボ β は競合結果として提示しない）。「supported」の根拠を year-by-year に置き換え、ただし **A-1 の goods-services 交絡は year-by-year にも効く**ため「cost-push **固有**とは断定不可、整合的どまり」と添える。pooled プラセボを論文で使うなら within/between 分解を別途要する（本レビューでは未実施）。

### A-3. Shift-share 推論（SE）の few-shocks 問題 [MAJOR]

- 文献に Adao-Kolesár-Morales (2019)・Borusyak-Hull-Jaravel (2022) を挙げるが、その exposure-robust SE を**実装していない**（entity-cluster SE のみ、`cost_push_panel.py:242`）。
- 単一集計 shifter（P_import_total）× IC の設計は実質「ショック1本」。time FE 下で識別変動は IC×（ほぼ単調な時間トレンド）。**n=164 は独立情報を過大表示**、p=0.002 は楽観的な可能性。
- FD 2021→22（comp-excl）β=0.371, p<0.001（n=39）は相対的に clean だが**単一エピソード依存**。
- **推奨**: BHJ exposure-robust か AKM の SE を実装。最低限「単一集計ショックゆえ有効自由度は小」と限界明記。

### A-4. 改善案（建設的・貢献を増やす）: group-specific shift-share

Phase 1 が5グループ別価格を持つのに識別は集計に潰している。
IC を 5グループ別 `IC_{c,g}` に分解し `ΔCPI_{c,t}=Σ_g β_g(IC_{c,g}×P_{g,t})+FE` とすれば、(a) 独立 shifter が複数になり識別変動・BHJ 推論が意味を持つ、(b) **グループ別転嫁の異質性**が出て論文の貢献も増す。現設計から自然な拡張。

## B. 交易損失・所得流出（Phase 1）

実際の算出式（`trade_loss.py:173-177`、IC は不使用）:
- UB: `M_g(2020) × (P_import_g − 100)/100`
- NET: `M_g(2020) × (P_import_g − P_domestic_total)/100`

### B-1. 「所得流出」概念の取り違え [MAJOR / reframe で対応可]

- NET は**相対価格スプレッド指標**であって所得フローではない。
- 証拠: 化学グループ NET が 2024 −341億 / 2025 −1505億 / 2026 −1704億と**負**（=所得が日本へ流入?）。フローなら符号反転は不自然。
- 「内閣府 交易利得・損失と comparable」（`trade_loss.py`）は、輸出側利得を引かず・5品目限定・国内CGPI使用の点で定義が異なる（内閣府2022≈−12〜16兆 vs 本推計34.6兆）。
- **推奨**: 「所得流出額」→「**輸入コスト負担**（の粗推計）」。交易損失（SNA）との概念差を注記。

### B-2. 数値の内部不整合 [要修正・単純ミス]

- 「34.6兆円（エネルギー67%）」: **34.6兆は NET 総額、67%は UB（40.7兆）のエネルギーシェア**。NET のエネルギーシェアは実データで **73.8%**（25,493/34,558）。
- 正: 「34.6兆（エネルギー73.8%）」**または**「40.7兆（エネルギー67%）」に統一。CLAUDE.md・progress.md・feasibility.md 全てに波及。

### B-3. doc と code の式の乖離 + 先行研究照合 [要修正]

- analysis-plan.md:44「IC×輸入価格変化率×輸入額」だが実コードは `M×ΔP`（IC なし）。
  - ※直接輸入財に IC を掛けるのは二重割引で不適切 → **コードの方が合理的**。doc を実態に合わせる。
- 齊藤2022（GNI比4.6%≈25.8兆）との照合: 本推計34.6兆 = **GNI比6.2%**。同オーダーだが1.3倍。「整合的」→「概念差（輸出利得未控除・5品目限定）を踏まえ同一オーダー」に。

### B-4. 輸入含有率 IC>1 [MAJOR / 要修正]

- `sector_import_content.csv`: sector 61=**1.070** / 231=1.018 / 271=**1.100**。含有率（シェア）が1超は経済的に不可能。
- 原因候補: `(I−A)^{-1}` を輸入比率ベクトルに適用（`io_utils.py`）。日本の競争輸入型標準は `(I−(I−M̂)A)^{-1}`。分母 `output+imports`（輸出未控除）も一因。
- **影響**: 34.6兆には不使用だが、**Phase 2 の IC_c（β回帰の右辺）と Phase 3 の content に波及**。グループ平均（max 0.64）では隠れるが、審査でセクター値を見られると含有率構築全体が疑われる。要再構成 or 検証。

## C. シミュレーション・政策評価（Phase 3）

### C-1. 政策評価のトートロジー [CRITICAL / reframe 必須]

- 「エネ補助50%が逆進性101.6%解消」「複合123.8%」は、**行動反応（需要弾力性・MPC・一般均衡・転嫁）ゼロの会計恒等式の機械的帰結**。
- 証拠: δ感度で解消率 **99.5〜99.6%（δ=0.4〜1.0 で不変）**。動学を変えても不変 = 「エネルギーが格差の支配的決定因」という会計構造のみに依存。100%超は補助で符号逆転するだけ（支出シェア差×補助規模の算術）。
- 「エネが逆進性を駆動 → エネ補助で解消」は**循環**。因果的政策効果ではない。
- **推奨**: 「政策評価」→「**ceteris paribus 下の分配会計（incidence accounting）**」。マイクロシミュレーションの帰着計算自体は正当だが「行動反応を含まない事前会計」と明記。実際の補助は消費量変化・財源還流・転嫁で結果が変わると限界に。

### C-2. RMSE「検証達成」の不整合 [MAJOR]

- 9.744pp は **Koyck モデル出力（cost-push のみ）vs 実績CPI（cost-push+demand-pull）** の誤差。構造的に過小予測になるのは当然で、これを「目標<10.5pp 達成✅」と検証成功にするのは不整合（自己矛盾: analysis-plan.md:131 は同じ過小推定を「デマンドプル起因でモデル欠陥でない」と認めている）。
- 10.5pp 目標は decision-log に根拠記録**なし**（事後設定/HARKing 疑念）。9.744 vs 10.5 は薄い。
- むしろ「**誤差 = デマンドプル残差で時間と共に拡大**（2024 ~−6.8pp）」は findings として価値。validation でなく **decomposition** として提示すべき。
- 補足: 生成コードは `notebooks/04_phase3_simulation.ipynb:124-134` にある（Phase3 コード監査の「コード無し」指摘は誤り。.py のみ読んだため）。

### C-3. δ=0.55「RMSE最小化推定値」の過大表現 [MINOR]

- 独立 grid（本レビュー）: RMSE_shock 最小は **δ=0.60（9.562）**、0.55 は 9.576。曲面は [0.50,0.70] で平坦（9.56–9.58）→ **δ は弱識別**。
  - ※再現値 ≈9.58（δ=0.55）と論文 headline **9.744** の ~0.17pp 差は sample/merge 差と思われる（深追いせず）。
- 「推定値（estimated）」は標準誤差を要する確定推定の外観。実体は **calibration**。「半減期≈10.4ヶ月の calibration、RMSE は δ に鈍感」と正直に。厳密な最小は0.55でなく≈0.60。

### C-4. β=0.431 で Leontief 出力をスケール [MAJOR / 説明必須]

- β は**消費者価格**（CPI中分類）の reduced-form 回帰係数。Leontief `p=L^T m` は**生産者価格**の構造乗数。異なる変数空間の係数を構造出力に乗じている（`io_price_model.py:168,370`）。
- マークアップ・流通マージン・税込みの混合概念を生産者価格ベクトルに直掛けする単位的根拠は弱い。
- **推奨**: 「完全転嫁（β=1）モデルを実績に縮める**経験的スケーリング係数**」と明示（構造パラメータと称さない）。β=1版を併記済みなので、それを正当化に使う。
